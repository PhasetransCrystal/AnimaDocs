# 日间发射场 / 夜间轨道 · 需求讨论稿

> 用途：单开会话讨论用。本文只描述现状、意图和待决问题，不是实现方案。
> 代码基线：`e34a7ea`（main，已推送）。细节以代码为准。

## 0. 一句话概念

日间是地面的“发射场”（平面制图、钴蓝、纸白、墨黑），夜间是外层空间的“轨道”（石墨、朱红盘、黄铜刻度）。日夜切换不再是两张画交叉淡化，而是一次“升空 / 降落”。文档页沿用同一套“高度 / 宇航飞行”语言，但阅读优先。

## 1. 设计现状

### 1.1 首屏结构

- `pages/index.tsx`：`header.heroBanner` > `.heroArt`（`aria-hidden`，由 `useHeroPaging` 写 inline `translateY`，封面 -> 落地页之间最多位移 120px）> `VisualStudy`。
- `VisualStudy/index.tsx`：容器 `[data-theme-art]` 下两张 svg，`.dayPlate[data-art-mode=day]` 和 `.nightPlate[data-art-mode=night]`。两张都是 `viewBox 0 0 1440 900`、`xMidYMin slice`，坐标系一致，非当前模式 `display:none`。
- 首屏翻页：桌面端 wheel / 键盘在封面与落地页之间吸附（`useHeroPaging.ts`，不能改坏）。滚动中或离开封面时 `.heroArt[data-art-paused]` 暂停美术动画。

### 1.2 日间底板 DayAtlas（地图集 / 测绘）

- 左侧 wash 色块（种子 LCG 20260816），右侧钴蓝阶梯陆块（`rotate(-7 960 220)`，land0-6 色阶 + 投影 + 网格）。
- 旋转方块瓷砖场（mask 渐隐），导引圆 `(640,150) r170` + 36 刻度，路线折线（ghost / main / crawl）+ 5 个路线节点闪烁，测绘线、等宽标注、图版编号、套准标记、小方块标记（原黄铜，现为墨黑）。
- 动效：导引圆虚线爬行、路线虚线爬行、节点闪烁（都是 dashoffset / fill-opacity，非合成层）。

### 1.3 夜间底板 NightObservatory（观测 / 轨道）

- 焦点 `FOCUS = (1010, 236)`：朱红圆盘 + 偏移透镜（lensDrift）+ 颗粒、十字准线、刻度环（tickSpin）。
- 模糊阶梯地形（terraceDrift，在 blur filter 内）、径向渐隐网格。
- 轨道组 `rotate(-16)`：椭圆 rx 300 / 430 / 560，两条彗星虚线；卫星小球在 `(FOCUS.x-404, FOCUS.y-38) = (606, 198)`，带脉冲环。
- 像素点闪烁、加号标记。手机端 ≤640px 夜间底板放大到 205%，`overflow: visible` 做上方出血。

### 1.4 切换现状

- `clientModules/themeTransition.ts`：拦截主题按钮点击 -> `document.startViewTransition()`，在更新回调中加 `html.theme-vt` 并重放点击。旧快照静止不透明，新快照用自定义 `animaThemeFadeIn` 淡入 520ms（避开 Chrome UA 的 plus-lighter 过曝）。期间美术动画暂停。
- 回退：不支持 VT 时 `theme-transitioning` 520ms 颜色过渡 + 底板交叉淡化。reduced motion 下直接切换。
- 已知问题：交叉淡化中点混色（灰底、蓝红混成紫）。用户已认可流畅度；封面渐变与 logo 过渡可忽略。
- 性能现状（生产构建、4x CPU）：日间 7 个合成层 / 26MB，夜间 30 层 / 48MB；一次切换主线程约 70-90ms，主要是约 600 个元素的样式重算和 SVG 文本布局，属于换主题本身的成本。

### 1.5 文档页现状

- 文档页已有日夜底板与装饰（`css/art-adapters.css` 中的文档相关规则，含 mask 渐隐），细节新会话先盘点。
- 现有小元素：侧栏当前项方块标记、h1 上方短划线对（日间墨黑 / 夜间黄铜）。
- 约束：`website/docs/**` 内容不能改、不能 stage，趋同设计只能通过主题 CSS、swizzle 组件或 clientModule 实现。

## 2. 需求一：首屏高度条 + 升空过渡

### 2.1 高度条（高度计）

- 竖向高度计，日间指向地面读数 `325 m`，夜间指向太空读数 `799,000 km`。
- 两端量级差约 2.5×10⁹，线性刻度无法同时表达，倾向对数刻度（10 m、1 km、100 km 卡门线、36,000 km 地球同步轨道、384,400 km 月球、799,000 km）。刻度点同时也是升空过程中的“里程碑”。
- 可访问性：读数是真实文本放在 DOM 中（屏幕阅读器可读，或给出“当前模式”说明）；刻度和指针等装饰加 `aria-hidden`。
- 初步位置想法：首屏左侧或右侧边缘竖条，不和目录面板（`signalPanel`）及标题抢位。需要确认桌面 / 平板 / 手机三档的位置。

### 2.2 升空过渡（日 -> 夜）

初步想法：日间底板上的某个起点元素，过渡为夜间外轨道上的卫星小球，效果类似发射升空。其他美术元素按顺序出现、消失或移动。参考编排（时长待定，按 1.2-1.8s 估算）：

| 阶段 | 视觉 | 高度读数 |
| --- | --- | --- |
| T0 点火 | 日间起点方块（候选：路线终点节点或墨黑小方块）亮起，路线线条收束 | 325 m |
| T1 离地 | 起点沿弧线上升；陆块、瓷砖、wash 下沉并淡出，地平线压低 | 快速滚动，对数推进 |
| T2 穿越大气 | 背景从纸白过渡到石墨（可经过一段钴蓝 / 深蓝的“大气层”）；网格拉伸 | 经过 100 km 卡门线刻度 |
| T3 入轨 | 朱红盘升起，轨道椭圆依次描出，小球落到外轨道卫星位置 `(606,198)` | 接近 799,000 km |
| T4 稳定 | 刻度环、像素点、加号标记出现，常驻动画恢复 | 799,000 km |

- 夜 -> 日反向做成“降落 / 再入”，可以更短，不要求完全对称。
- 入口：现有 VT 钩子（更新回调内）。可选做法：VT 只负责页面颜色，首屏美术在新快照中先隐藏，由首屏自己的编排动画接管；或者完全由 VT 伪元素 + clip-path 完成。
- reduced motion：直接切换，高度读数立即跳到目标值。
- 只在首屏可见时播放完整编排；不在首屏（已滚动到下面或在文档页）时退回普通切换。

### 2.3 约束与风险

- 性能：切换本身已有约 70-90ms 主线程成本（4x CPU）。编排动画尽量只动 transform / opacity / dashoffset，且不能叠加在样式重算的那一帧上（考虑在 VT 结束后再开始，或先启动再换主题）。
- 两张底板现在互斥 `display:none`。编排期间需要两张同时存在（或一张中间态底板），注意层数和内存（夜间已有 30 层）。
- 坐标：两张底板共享 1440×900 坐标系，起点和卫星的位置可以直接对应；手机端夜间底板是 205% 放大偏移版，需要单独换算或简化编排。
- 不能破坏 `useHeroPaging`（翻页吸附、`data-art-paused`、inline transform）。
- 浏览器：VT 不可用时的回退路径要保持可用（至少保留现在的交叉淡化）。

## 3. 需求二：文档页趋同设计（高度 / 宇航飞行）

原则：首屏是“表演”，文档页是“仪表”。只做低干扰、可读性优先的结构隐喻，不放常驻动画。候选设计点（待筛选）：

| 编号 | 设计点 | 日间（发射场） | 夜间（轨道） | 实现提示 |
| --- | --- | --- | --- | --- |
| F-01 | TOC 高度计 | 右侧 TOC 竖轴变成刻度尺，当前标题为指针 | 同左，刻度为黄铜 | 只改 TOC 样式；当前项已有 active class |
| F-02 | 阅读进度 = 高度 | 页面顶部或 TOC 顶端显示“高度”读数，随滚动对数上升 | 同左 | 读数 aria-hidden，不替代真实进度信息 |
| F-03 | 侧栏飞行计划 | 分类 = 任务阶段，当前项 = 当前航点 | 当前项为轨道上的小球 | 侧栏已有方块标记，可延伸为航点线 |
| F-04 | T+ 章节编号 | h2 前加 `T+01` 等等宽小标 | 同左 | CSS counter，不改 md 内容 |
| F-05 | h2 卡门线 | h2 分隔线做成带“100 km”刻度的细线 | 线变成弧形轨道 | 纯 CSS 背景 / 伪元素 |
| F-06 | 上一页 / 下一页对接 | 分页卡片做成对接端口，箭头为对接方向 | 同左 | swizzle 或纯 CSS |
| F-07 | 代码块遥测面板 | 代码块头部加通道标签和细刻度框 | 深色面板 + 琥珀状态点 | 只改样式，不影响复制按钮 |
| F-08 | 告示 = 任务通报 | admonition 标题做成 `NOTE / CAUTION` 通报格式 | 同左 | 现有 alert token 继续用 |
| F-09 | 底板视差 | 滚动时网格轻微下沉，模拟上升 | 星点 / 网格缓慢后退 | 只用 transform；reduced motion 关闭；可选项 |
| F-10 | 页面高度分层 | 文档按目录层级对应不同“高度带”（入门 = 地面，理论 = 轨道） | 同左 | 需要路由到层级的映射，成本较高 |

约束：

- `website/docs/**`、`website/sidebars.ts`、`website/static/**` 不改。
- 正文区不放装饰；对比度、行宽、代码可读性不得下降。
- 所有新增动效遵守 reduced motion 和滚动暂停约定（见 `DESIGN_ASSETS.md` 的“实现约定”）。

## 4. 核心问题（待讨论）

1. 高度条放在哪里？只在首屏出现，还是首屏和文档页共用一个组件（文档页里同时作为 TOC 或阅读进度）？
2. 日间起点用哪个元素？（路线终点节点、某个墨黑小方块，或新增一个“发射台”标记）它与夜间卫星的对应关系是否需要在静态画面里就能看出来？
3. 升空编排的总时长和触发范围：每次切换都播放，还是只在首屏可见时播放？是否允许用户在播放中再次切换（中断 / 反转）？
4. 技术路线：A）VT 换颜色 + 首屏自有编排（两张底板短暂共存）；B）全部放进 VT 伪元素（clip-path / 遮罩擦除，成本低但“升空”感弱）；C）先做中间态（大气层渐变 + 小球）的单独图层。
5. 中点混色问题是否顺带用这次编排解决（例如用“大气层”色带覆盖中点），从而不再需要圆形揭示方案？
6. 读数格式：`325 m` / `799,000 km` 是否中英混排、是否显示中间值滚动，是否需要单位换算（m -> km）的动画处理？
7. 文档页候选 F-01 到 F-10 中，第一轮做哪几项？是否接受 F-09 这类滚动驱动的动效？
8. 手机端：是否简化为“读数跳变 + 小球上升”，不做完整编排？
