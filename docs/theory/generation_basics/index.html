ai生图基本原理

对于最基础的工作流，其实同时使用到了三种模型（也就是我们之前下载的三种）：生图主模型，文本编码器，VAE。

基础流程​

生图阶段的基本流程是：

提示词 -文本编码器-> 条件向量 + 空白潜空间 -主模型-采样节点-> 图像潜空间 -VAE解码-> 可读图像

从训练顺序而言：

已有文本编码器，已有VAE->基于已有模型训练主模型

主模型与辅助模型

绘图主模型本身无法直接理解提示词文本内容——模型基于文本编码器产出的语义向量序列来训练，因此也只能理解对应模型产出的语义向量序列。这也是为什么模型需要使用配套的文本编码器才能正常运行。

vae同理，其与latent的通道数与内容挂钩。

发生了什么​

ai生图的核心是“采样”节点。

想象一张充满噪点的画布：模型的任务就是根据要求，也就是提示词把这堆噪点变成可读的图像。

与现实绘画的流程不同，ai生图并非模型直接“指定某个位置的像素是什么颜色”或是“在某个位置画一条线，涂色”，而是“降噪”： 模型会对当前的画布内容进行处理，并生成一份“降噪表”，包含画布上每个位置对应的修正量； 节点根据一定算法将修正量叠加到原始画布上。这个过程重复进行几次，每一次都比上次更加优化，最终就得到了一张有效图像。这一过程类似逼近拟合。

实际情况比这稍微复杂一些，这里我们结合节点的参数来讲：

  1. 画布-潜空间：直接使用像素的四通道（argb，不过大部分模型其实是三通道，丢弃透明度通道）作为画布会导致处理效率极低，难以达到实用化需求。 潜空间对象具有更高的通道数，并将相邻像素合并到同一个潜空间“像素”上。

    不同的模型使用的潜空间通道数不同，通道数通常由cui运行时自动判断，不需要手动设置（另外像素压缩也是，所以空白latent节点填的长宽与实际程序中潜空间对象的大小存在换算关系）

    潜空间对象通常是一个四维张量([批大小,通道数,长/压缩比,宽/压缩比])

  2. 需求-文本编码：使用文本编码器将正/负面提示词进行编码。这就是一个标准的基于Transformer文本编码流程，文本先做切分查表再做自注意力， 最终输出一个代表语意的二维张量([token长度,单token语意向量长度])，下文称为语意向量序列/提示词，包含了模型能“读懂”的提示词的完整内容或压缩后的文本特征。 有些模型可能还会同时用好几个文本编码器一起处理然后合成。

    由于模型的训练本身就基于对应语言模型产出的语义向量序列，因此不同模型的文本编码器不能混用。

    根据不同的模型，可能会对语意向量序列进行额外的处理，例如添加标记符，短token序列长度补齐等。 提示词中的加权行为也在这一步被处理，但不是直接由语言模型负责，而是对输出的语意向量序列中对应位置token的语意向量直接进行缩放。

  3. 绘制-采样：画布(即潜空间)在输入之前是完全空白的，在进入采样节点后会根据“降噪(denoise，百分值)”和“种子(seed)”添加噪音(也就是随机初始化张量内的数值)； 文生图时是画布由“完全无图像”到“完整图像”的生成，通常降噪值为1.

    在这之后，模型会循环处理一定次数(步数，steps)，每次把当前的latent数据，提示词，当前的降噪程度分位等交给模型进行计算处理。 模型并不会直接输出处理后的latent数据，而是输出一张“降噪表”，即和原始latent在结构上完全对齐的张量，可以被近似视为模型认为原latent上每个数值位置需要减去的值。 然后节点再根据一定规则对输出和原始latent进行处理，并将数据送入下一循环。

    几个小要点，这一过程还伴随着其它一些处理细节：

    1. cfg：这一数值决定了正负面提示词的混合比例。负面提示词的语义向量序列与正面提示词的处理相似，交给模型和未修改的latent以及其它数据一起进行处理，同样输出一个与原始latent对齐的张量；

      对于正，负提示词的两组输出(暂命名t-p,t-n，均为与原始latent对齐的张量)，节点会基于cfg进行计算实际的混合后输出t-o：

      to=tn+cfg (tp−tn)=cfg tp−(cfg−1) tn\mathbf{t}_o = \mathbf{t}_n + \mathrm{cfg}\,(\mathbf{t}_p - \mathbf{t}_n) = \mathrm{cfg}\,\mathbf{t}_p - (\mathrm{cfg} - 1)\,\mathbf{t}_nto​=tn​+cfg(tp​−tn​)=cfgtp​−(cfg−1)tn​

      可以近似理解为，实际的“降噪表”是正负提示词之间的数值差，cfg数值会进一步缩放这一数值。由于没有进一步的限制，高cfg很可能导致出图过曝扭曲，低值则可能导致图片不成形。

      另外，从公式不难看出，cfg=1时，t-o = t-p，此时负面提示词完全不起作用。对于标准模型这一操作大多数情况下会导致出图不成型， 但对于许多蒸馏版模型(例如Anima-Turbo)，通常在训练时就按照该标准执行，反而只能在该数值下(或附近)正常工作。实际配置推荐请以模型发布方信息为准。

    2. 调度器(scheduler)与求解器(solver)：降噪程度数值会被作为原始数据之一输入模型，而“降噪程度”这一数值本身并不一定随着步数增加而线性演进。

      模型在训练上可能采用非线性的降噪演进来让模型在不同时间段具有更好的倾向性，或是将更多的能力投入在某一阶段。

      调度器负责根据一定算法实现(总步数,当前步数,采样降噪总值)->降噪分位的映射，不同的调度器选项具有不同的算法，会影响模型在每一步上获取到的“降噪分位”数值。

      求解器则更加复杂，它会根据降噪分位，步长，“降噪表”等各项数据结合自身算法对原latent对象进行处理。主要分三个方面：

      • 阶数：一般情况下(Euler)，求解器根据本组数据运算后和原latent相减；但一些求解器(例如二阶的Heun)可能会在完成这一步后再进行一次额外处理。这会让结果更精确，但会占用更多算力，且精确不等于出图效果一定好。

      • 步数：一些采样器(例如双层的dmpp-2m)还会引用前序步的数据结果进行混合处理

      • 加噪：一些采样器(例如带ancestral的)还会额外添加回一些随机噪音扰动。这可能增加画面活性，但也可能导致出图的不稳定性加剧。

    经过多轮处理，latent会越来越接近需要的有效图像对应的画面。但正如我们之前提到的，latent本身是一个高维矩阵，大量的通道数与训练而来的语意使其不直接具有可读性。 因此，我们还需要最后一步，把latent转换为真正可读的图像。

  4. 产出-VAE解码：Variational Autoencoder，变分自编码器。它的作用是将可读图像与latent进行转换，将相邻视觉像素压缩进高维潜空间像素，或者反过来。

    它还有一些别的特性，例如设计和训练层面的概率化和干扰训练，用于提高出图质量。这里不深入。

    由于压缩性质本身，对于高精度细节，vae可能无法实现极致的还原。这仍然可能导致细节丢失。比如你将一张照片丢给vae编码再解码，在像素级细节上很可能会发生微小扰动。

总结一下，正如我们上面提到的，生图的基本流程是提示词 -文本编码器-> 条件向量 + 空白潜空间 -主模型-采样节点-> 图像潜空间 -VAE解码-> 可读图像， 而在采样这一步，程序会根据一定算法反复循环执行，让图像慢慢从混沌接近可用。

换言之，ai生图不是“模型根据提示词想出该画成啥样”，而是“模型每次根据提示词猜着对画面改一点，然后再基于改完的图继续寻思继续改，重复数次”

如果把未完全降噪的latent拉出来走vae，虽然图像大概率不符合通常对人类艺术和审美的大众化理解，但我们仍可以看出一些模型通过训练自己学到“处理顺序技巧”，以Anima为例：

  • 在步数较低时，图像会逐渐由混沌变出轮廓和大致的人物颜色片（有点像近视眼摘掉眼镜的感觉，哎呦）
  • 在后续步数中则通常不会改变构图，主要是改进画风，优化细节等（之前看的时候有个奇怪的发现，眼睛似乎都是在最后几步成型的，在之前总是会被解码成奇怪的错误颜色）

所以anima有个比较神秘的小技巧：由于anima的早期构图阶段对种子不敏感，角色姿势上遵循度会更高，但有时也会导致构图多样性偏低。 因此可以在文生图时只把降噪拉到0.9之类的，提高多样性，但也可能损失稳定性。嘛，抽卡游戏。

另外说到这个我很想多一句嘴，有人说ai绘图是拼石块，其实按照原理它还真不像拼石块，更像是你把一个雕像砸碎了然后重新捏回去还要求每个极小碎块都复原到原位置。

石块？抱歉，没那么大块。要是真能做那么大块的那ai的精度和还原度能力绝对不止现在这个水平。
